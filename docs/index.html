Pedido de uma linha entra. Prompt pronto sai.

Prompt Enhancer transforma uma tarefa mal descrita em um prompt estruturado, pronto para colar na sua IA de código. Depois, gera a mensagem de commit e a descrição do PR a partir do diff.

      Fluxo
      
Do pedido ao Pull Request, sem escrever texto repetido

      
Três telas que seguem a ordem do trabalho: pedir, commitar e abrir o PR.

    

    

      

        01 · Prompt
        
Prompt de vibecoding

        
Descreva a mudança em poucas linhas e, se quiser, cole um Context Pack com caminhos, trechos e convenções. Sai um prompt em Markdown, pronto para Copilot, Codex, Continue ou qualquer IA com acesso ao repositório.

        
entrada: tarefa + contexto opcional

      

      

        02 · Commit
        
Mensagem de commit

        
Cole o resultado de git diff --staged. O app devolve uma linha no padrão Conventional Commits, no imperativo e com até 72 caracteres.

        
saída: feat(users): rename nome field to titulo

      

      

        03 · Pull Request
        
Descrição de PR

        
Cole o diff do branch ou a lista de commits. A descrição segue o template de PR que você salvou nas configurações.

        
entrada: git diff origin/main...HEAD

      

    

  






  

    

      

        Anatomia
        
Todo prompt sai com a mesma estrutura

        
A IA de código erra menos quando sabe o objetivo, os limites e como o resultado será conferido. Por isso a saída tem sempre cinco seções.

      

      
    
        
  • # GoalO objetivo em uma frase.
    • 
        
  • # ContextSó os fatos úteis: stack, rotas, padrões e caminhos suspeitos.
    • 
        
  • # ConstraintsO que não pode mudar: build, padrões, escopo mínimo.
    • 
        
  • # TasksPassos ordenados, cada um acionável.
    • 
        
  • # Acceptance criteriaItens verificáveis que dizem quando a tarefa acabou.
    • 
      

    

    

      

        
Direct implementar já

        
Para mudanças em que você já sabe onde mexer. As tarefas vão direto à implementação.

      

      

        
Two-phase descobrir → implementar

        
Para código que você não conhece. A fase 1 manda a IA localizar arquivos e listar o plano sem editar nada. A fase 2 executa.

      

      

        
Histórico

        
Salve o par pedido e prompt para reusar depois. Cada usuário entra com a conta Google e tem as próprias configurações e chave.

      

    

  






  

    

      Modo Caveman
      
Corta as palavras. Mantém a instrução.

      
Com o Caveman ligado, o prompt perde artigos, conectivos e preenchimento. Nomes, caminhos e código ficam exatos. Menos tokens enviados a cada execução.

    

    

      

        
Normal21 palavras

        
O objetivo desta tarefa é renomear a função getUser para fetchUser no arquivo de serviços para manter a consistência da API.

      

      

        
Caveman9 palavras

        
Renomear getUser para fetchUser em serviços para consistência API.

      

    

    

      
Sem artigosO, a, um, uma: fora. A IA entende igual.

      
Frases curtasFragmentos no padrão item, ação, motivo.

      
Código intactoIdentificadores, caminhos e trechos nunca são abreviados.

    

  






  

    

      Modelos
      
Escolha onde o modelo roda

      
Provedor e modelo são configurados por usuário, e podem ser diferentes para prompt, commit e PR.

    

    

      

        Nuvem
        
Groq

        
    
          
  • Usa a sua própria chave de API.
    • 
          
  • Em modo auto, consulta os modelos disponíveis e escolhe um.
    • 
          
  • Padrão: llama-3.3-70b-versatile.
    • 
        

      

      

        Local
        
Ollama

        
    
          
  • Nada sai da sua máquina: o diff e o código ficam locais.
    • 
          
  • Detecta os modelos instalados e prefere os de código para commit e PR.
    • 
          
  • Se o modelo configurado foi removido, tenta outro instalado.
    •

      Rodar
      
Sobe em um container

      
App e banco sobem juntos com Docker Compose. Você só precisa das credenciais do Google OAuth e de uma chave Groq ou um Ollama rodando.

    

    

      

        
Clonar

        
git clone https://github.com/lucodifier/enhance-prompts.git
cd enhance-prompts

      

      

        
Configurar o ambiente

        
Copie o modelo e preencha NEXTAUTH_SECRET, as credenciais do Google OAuth e, se for usar, a chave Groq.

        
cp .env.docker.example .env.docker

      

      

        
Subir

        
Depois, aplique os scripts SQL da pasta scripts/ em ordem e abra http://localhost:8080.

        
docker compose up -d --build
